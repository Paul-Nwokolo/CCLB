CCLB PARISH SITES — UI/UX DESIGN REVIEW
Catholic Church of the Lord's Baptism, Osapa / Lekki, Lagos
Reviewed: 15 September 2026
Scope: cclbparish.com, give., harvest., join.  — analysis only, nothing changed

HOW THIS WAS MEASURED (read this first — it affects how much to trust each item)

Each page was rendered at an exact layout viewport of 375, 768 and 1280 CSS px
and measured in the live DOM: computed font sizes, element rectangles, tap-target
sizes, gaps to nearest interactive neighbour, horizontal overflow, section
heights and above-the-fold inventories.

The three widths could not be produced by resizing the browser window — the tab's
render surface is fixed, so window resizing never changed the layout viewport and
no mobile media query ever fired. Instead each page was re-rendered from its own
origin into a same-origin frame of exactly the target width, with the desktop
scrollbar suppressed so that both the layout viewport and the `vw` unit equal the
target exactly.

The method was validated before use: at a matched 831px viewport the harness
reproduced the real page's values exactly — h1 41.55px, h2 36px, body 13.6px,
document height 3255px, hub card 324px — identical on every metric. Numbers below
can be treated as real measurements, with two disclosed exceptions:

  (a) Third-party Tally embeds do not load inside the harness. The empty form box
      is a harness artifact, NOT a site defect. Tally was verified separately on
      the live page and it loads correctly (see HARVEST / JOIN notes).
  (b) Because Tally did not load, page heights for harvest and join are measured
      with the form at its initial height attribute (500 / 520px). Real pages are
      taller once the form expands.

Anything not directly observed is labelled INFERENCE. Everything else was seen or
measured. Contrast was only computed where the background is a solid colour; over
gradient/image backgrounds it is reported as not verifiable rather than guessed.

Screenshots: captured at each width and shown inline in the chat transcript
alongside this review (the browser capture in this environment returns images to
the conversation and cannot write image files, so they could not be bundled).
Captures referenced below: hub 375 fold, hub 768 fold, hub social band 1:1,
hub carousel 375, give 375 fold, harvest 375 fold, join 375 fold.

3.2 BODY TEXT
    hub 2 sizes (18, 13.6) · give 6 sizes (19.2, 18, 16, 15.2, 13.6, 13.12) ·
    harvest 3 (18, 15.2, 13.12) · join 4 (18.4, 16, 15.2, 13.12).
    Seven distinct sizes (19.2, 18.4, 18, 16, 15.2, 13.6, 13.12) across fifteen
    declarations, for what should be three roles: lead, body, label.

3.3 BUTTONS
    give:    eight filled variants — radius 14px AND radius 999px on the same
             page, heights 53 / 54 / 61 / 83px
    harvest: two variants, both radius 999px, height 53px
    hub:     no filled buttons; card links and 44px icon circles only
    join:    none
    Pick one pill (one radius, one height, one padding) and one secondary style.

3.4 HEADER
    hub none · give 67px · harvest 71px · join 71px.
    Pill label: give "Give" (in-page anchor) · harvest "Harvest" (in-page) ·
    join "Give" (off-site). Give the hub the same topbar and make the pill mean
    one thing everywhere.

3.5 HERO
    hub 428px light · give 782px navy gradient with a second crest ·
    harvest 321px light · join 391px navy.
    Two heroes are dark, two are light, and they differ 2.4x in height. Pick one
    hero pattern with one height band.

3.6 SECTION HEADINGS
    On the hub, `#gallery` and `#social` headings are `visually-hidden` while
    `#church-life` and `#contact` are visible. Either a section has a visible
    heading or it does not — this should not vary within one page.

3.7 CREST
    `<img>` on give and harvest; `span` + CSS background-image on join; `<img>`
    on the hub. Give consumes two crests in its first 400px.

3.8 FOOTER
    Heights at 375: hub 410 · give 372 · harvest 341 · join 372.
    Footer h3: 21.06px on the hub, 19.2px elsewhere. Footer email is a 17-21px
    target on every site. The footer is the one component that is nearly
    identical already — worth making it literally identical.

3.9 TAP TARGETS — the same four failures repeat everywhere
    (a) topbar brand link 40px tall — give, harvest, join
    (b) contact phone/email 20px tall — hub, give
    (c) footer email 17-21px tall — all four
    (d) carousel dots 14x14px — hub
    Fixing (a)-(c) is a shared-component change, not four separate fixes.

3.10 CONTENT WIDTH ON SMALL SCREENS
    Interactive content is systematically inset at 375: give inputs 261px,
    join form 261px, join notice text 175px, harvest form 293px — all inside a
    327px card in a 375px viewport. One mobile padding scale (say 16px at the
    wrap, 20px at the card, 0 nesting below that) recovers 60-150px of width
    across all four sites.

3.11 DESKTOP IS UNSERVED
    give, harvest and join are byte-identical in layout at 768 and 1280
    (give 4323px, join 1713px at both). Only the hub responds above 768 — and it
    does so at an awkward threshold, going two-up somewhere between 768 and 831,
    so iPad portrait gets the phone layout.

4. THE SOCIAL SECTION — WHAT IT IS NOW AND WHAT TO DO
================================================================================

WHAT IS THERE (measured, hub at 375)
  section#social — 375x172px, padding 64px 0, background rgb(237,242,248)
  ├─ div.section-head.visually-hidden → h2 "Connect with Us" (27.2px, INVISIBLE)
  └─ ul.social-bar — display:flex, gap:16px, justify-content:center, 1 child
     └─ a 44x44px, background rgb(16,42,67), border-radius 999px,
        SVG 24x24 in rgb(201,162,75) → instagram.com/cclblekki/
  Nearest other interactive element: 132.6px away.

So: 172 vertical pixels, a full-width tonal band, an invisible heading, and one
44px circle — with a flex container built for a row of icons holding exactly one.
The read of "sparse and unfinished" is accurate, and it is worse than it looks in
markup, because the heading that would explain the band renders to nothing.

SHOULD IT BE ITS OWN SECTION? No.
One link does not earn a full-width band, 64px of padding and a section heading,
and it will not earn them at three links either. More decisively: the footer
already carries the address, phone, email and Sunday Mass times — it is already
the "reach us" component. A separate social band immediately above it splits one
idea across two blocks and adds a tonal stripe between the contact section and
the footer for no structural reason. Folding social into the footer removes
172px, removes a band, removes a heading, and puts the icons where people look
for them.

RECOMMENDED — Option A: a social row inside the footer
  Put the icon row in the footer as a labelled row, not a section.
    - Keep each target 44x44 with a 12-16px gap (the existing `.social-bar` flex
      with gap:16px already does this — reuse it verbatim).
    - Replace the invisible h2 with a visible 13.12px uppercase label in the
      existing eyebrow style ("FOLLOW THE PARISH"), matching ADDRESS / SUNDAY
      MASS / PHONE in the contact block, so it inherits a pattern already on the
      page instead of introducing one.
    - Place it directly above or beside the existing footer contact line and let
      it sit on the footer's navy — gold-on-navy at 44px is already the
      established icon treatment in the contact block.
    - Net effect on the hub: 172px shorter, one fewer band, one fewer heading.

  Option B (only if the parish wants social to be a real destination)
  Keep a section, but give it enough to justify itself: a visible heading, a
  one-line invitation, the icon row, and the Instagram handle as text
  ("@cclblekki") so the account is identifiable without tapping. Do not ship a
  band with fewer than three links.

  Option C — not recommended
  Leave it as a section and add placeholder icons for accounts that do not exist.
  Dead links read worse than one honest link.

APPLYING IT CONSISTENTLY TO THE OTHER THREE
  give already contains the exact scaffold, switched off: a
  `section.section--band` with the heading "Stay connected", the line "Worship
  with us, follow along, and join parish life." and an empty `.hub-grid`, all
  under `display:none` (finding G-12). Two options, and they should not be mixed:
    - If Option A is chosen: delete that hidden section and put the icon row in
      the shared footer. All four sites inherit it at once, because the footer is
      already near-identical across them (3.8).
    - If Option B is chosen: the hidden give section becomes the template and the
      hub's `#social` should be rebuilt to match it, not the other way round.
  Either way, one component, defined once, used on all four — since none of
  give / harvest / join currently has any social link at all, and only the hub
  links to Instagram.

WHICH ACCOUNTS
  Only one is evidenced: instagram.com/cclblekki/. WhatsApp appears on give as a
  wa.me link used for gift confirmation, which is a transactional use rather than
  a "follow us" channel — worth deciding deliberately whether it belongs in a
  social row. Do not add Facebook / YouTube / X placeholders unless those
  accounts exist.

5. THE PHOTO CAROUSEL — DOES IT EARN ITS POSITION ON A PHONE?
================================================================================

MEASURED (hub at 375)
  section#gallery: y1090-1471, 381px tall — screen 2 of 5
  heading "Parish Photo Gallery": visually-hidden, so the strip is unlabelled
  slides: 2
  image: rendered 343x193 (16:9), natural 800x450, from images.unsplash.com
         slide 1 eager, slide 2 lazy
  controls, below the image, centred:
    "Previous slide" 44x44 (y1363)  ✓
    dots 14x14, 12px apart (y1378)  ✗ (finding H-1)
    "Next slide" 44x44 (y1363)      ✓
  no captions; alt text "Parishioners gathered in worship" / "A community
  gathering"

VERDICT — no, not in its current form.
Three separate problems, in order of severity:

  1. The content is not the parish. Both slides are Unsplash stock. The visible
     first slide shows a social gathering under string lights and is described in
     alt text as parishioners in worship. A gallery of stock strangers on a
     parish homepage costs trust, and it is the one thing here that no amount of
     layout work fixes. Two real photographs would outperform this immediately.
  2. Two slides do not need a carousel. A 2-item carousel adds arrows, dots,
     an interaction model and a hidden second slide in order to show one more
     photograph than a static image would. Two images side by side, or one
     full-bleed image, delivers the same content with no controls, no hidden
     state and no 14px dots to miss.
  3. At 193px tall and inset to 343px, it is a small window on a device that
     could give it the full width. If photography stays, take it edge-to-edge:
     drop the side padding, let the image run 375px wide, and raise it to a 4:3
     or 3:2 crop. That is also the one place on these four sites where the

APPENDIX A — DEVTOOLS HARNESS: REPRODUCE AND RE-CHECK ANY FINDING
================================================================================

Every measurement in this review came from the harness below. It is included so
the findings can be re-run after each fix rather than taken on trust, and so any
number here can be independently checked.

Browser window resizing does NOT work for this: on the machine this review was
produced on, the tab's render surface was fixed, so resizing never changed the
layout viewport and no mobile media query ever fired. The harness re-renders the
page from its own origin into a same-origin frame of an exact width instead.

--------------------------------------------------------------------------------
HOW TO USE
--------------------------------------------------------------------------------
  1. Open the site you want to test — the harness must run on that site's own
     origin. To test give., be on give.cclbparish.com; it will not work from the
     hub, because the sites are cross-origin to each other and all four send
     `Content-Security-Policy: frame-ancestors 'none'` plus
     `X-Frame-Options: DENY` (which is correct and should stay).
  2. Open DevTools → Console and paste the whole snippet once.
  3. Then:

       await CCLB.view(375)      // render at an exact 375px layout viewport
       CCLB.audit()              // print every check as console tables
       CCLB.to('#social')        // scroll the frame to a section, then screenshot
       CCLB.off()                // remove the harness, restore the page

     Other widths and a zoom factor for screenshotting:

       await CCLB.view(768, 1024)
       await CCLB.view(1280, 800)
       await CCLB.view(375, 812, 1.5)   // 1.5x visual zoom; layout stays 375px

     `zoom` is a CSS transform. It scales what you see for a legible screenshot
     and does NOT change the layout viewport, the media queries or `vw`.

--------------------------------------------------------------------------------
WHAT audit() REPORTS
--------------------------------------------------------------------------------
  overflowX    'none', or the elements crossing the viewport edge
  tapTargets   every interactive element under 44x44px, with its size, its y
               position and the distance to its nearest interactive neighbour
  headings     h1-h4 with computed size, line-height and font, and a
               `hiddenFromSighted` flag for visually-hidden headings
  measure      paragraphs and list items whose line length falls outside
               45-75 characters, with the column width that caused it
  sections     top-level section offsets and heights, for vertical budgeting
  aboveFold    everything intersecting the first screen, with its y range

--------------------------------------------------------------------------------
THREE THINGS TO KNOW BEFORE TRUSTING A NUMBER
--------------------------------------------------------------------------------
  1. Third-party embeds do not load in the harness. The Tally forms on harvest
     and join render as an empty box. That is the harness, NOT a site defect —
     both forms load correctly on the live pages. It also means page heights for
     those two sites are measured with the form at its declared height attribute
     (500 / 520px) and are shorter than reality. Verify anything form-related on
     the live page.

  2. The scrollbar must stay suppressed. The snippet injects
     `scrollbar-width:none` into the frame so that the layout viewport AND the
     `vw` unit both equal the requested width exactly. Without it, a desktop
     scrollbar makes `vw` resolve against the frame's outer width and every
     clamp()/vw-based font size reads too large — 2.8% too large at 831px and
     6.1% at 375px. `view()` warns if the layout viewport does not match what
     you asked for; if it warns, the type sizes are not trustworthy.

  3. Gradient and image backgrounds defeat automated contrast checks. A computed
     `background-color` of `rgba(0,0,0,0)` over a gradient reads as white and
     produces false failures — give's hero h1 reports 1.03:1 when it is in fact
     white on a dark navy gradient and perfectly legible. audit() deliberately
     does not report contrast for that reason. Check contrast by eye, or sample
     the rendered pixels.

--------------------------------------------------------------------------------
VALIDATION — WHY THIS CAN BE TRUSTED
--------------------------------------------------------------------------------
  Rendered at a layout viewport matching the real page (831px), the harness
  reproduced the live page exactly:

      h1 41.55px · h2 36px · body 13.6px · document height 3255px · card 324px

  Identical on every metric. The harness was then re-run against the hub at
  375px as a final check and returned precisely the findings recorded above:
  the five sub-44px tap targets (14x14 dots at 12px spacing, 156x20 tel,
  155x20 mailto, 162x21 footer email), no horizontal overflow, both
  visually-hidden headings ("Parish Photo Gallery", "Connect with Us"), and the
  section heights hero 428 / hub 662 / gallery 381 / church-life 1221 /
  contact 765 / social 172 / footer 410.

--------------------------------------------------------------------------------
THE SNIPPET
--------------------------------------------------------------------------------
(() => {
  const ID = 'cclb-probe';
  const W = window, D = document;
  const S = { html: null, hidden: null, frame: null, bodyStyle: '' };

  const build = (html, base) => html.replace(/<head([^>]*)>/i,
    `<head$1><base href="${base}">` +
    `<style id="cclb-fix">html{scrollbar-width:none!important;scroll-behavior:auto!important}` +
    `html::-webkit-scrollbar,body::-webkit-scrollbar{width:0!important;height:0!important;display:none!important}</style>`);

  const CCLB = {
    async view(width = 375, height = 812, zoom = 1) {
      if (!S.hidden) {
        S.hidden = [...D.body.children];
        S.bodyStyle = D.body.getAttribute('style') || '';
      }
      S.hidden.forEach(el => { if (el.id !== ID) el.style.display = 'none'; });
      D.documentElement.style.background = '#fff';
      D.body.style.cssText = 'margin:0;padding:0;background:#fff;overflow:hidden';
      D.querySelectorAll('#' + ID).forEach(el => el.remove());

      if (!S.html) S.html = await (await fetch(location.pathname, { cache: 'reload' })).text();

      const f = D.createElement('iframe');
      f.id = ID;
      f.setAttribute('srcdoc', build(S.html, location.origin + '/'));
      f.style.cssText = `position:fixed;left:0;top:0;width:${width}px;height:${height}px;`
        + `border:0;background:#fff;z-index:2147483647;transform-origin:0 0;transform:scale(${zoom})`;
      D.body.appendChild(f);
      await new Promise(r => setTimeout(r, 5200));

      S.frame = f;
      const d = f.contentDocument;
      const real = d.documentElement.clientWidth;
      if (real !== width) {
        console.warn(`[cclb] layout viewport is ${real}px, expected ${width}px — `
          + `vw-based type will read ${(width / real * 100 - 100).toFixed(1)}% off`);
      }
      console.log(`[cclb] viewport ${real}x${f.contentWindow.innerHeight}`
        + ` · document ${d.documentElement.scrollHeight}px`
        + ` · ${(d.documentElement.scrollHeight / height).toFixed(1)} screens`);
      return CCLB;
    },

    to(selector) {
      const d = S.frame.contentDocument;
      const t = d.querySelector(selector);
      if (!t) return console.warn('[cclb] no match for ' + selector);
      d.documentElement.style.scrollBehavior = 'auto';
      t.scrollIntoView({ block: 'start' });
      return CCLB;
    },

    audit() {
      const f = S.frame, w = f.contentWindow, d = f.contentDocument;
      const vw = d.documentElement.clientWidth, vh = w.innerHeight;
      const cs = el => w.getComputedStyle(el);
      const txt = el => (el.innerText || '').replace(/\s+/g, ' ').trim();
      const out = {};

      out.overflowX = d.documentElement.scrollWidth > vw + 1
        ? [...d.querySelectorAll('*')].filter(el => {
            const b = el.getBoundingClientRect();
            return b.width > 2 && (b.right + w.scrollX > vw + 1 || b.left + w.scrollX < -1);
          }).slice(0, 10).map(el => `${el.tagName.toLowerCase()}.${String(el.className).split(' ')[0]}`)
        : 'none';

      const sel = 'a,button,input,select,textarea,summary,[role="button"]';
      const hits = [...d.querySelectorAll(sel)].filter(el => {
        const c = cs(el), b = el.getBoundingClientRect();
        return c.display !== 'none' && c.visibility !== 'hidden'
          && +c.opacity > 0.05 && b.width > 1 && b.height > 1;
      }).map(el => {
        const b = el.getBoundingClientRect();
        return {
          label: (el.getAttribute('aria-label') || txt(el) || el.value || '').slice(0, 30),
          w: Math.round(b.width), h: Math.round(b.height),
          x: Math.round(b.x), y: Math.round(b.y + w.scrollY),
        };
      });
      hits.forEach((a, i) => {
        let g = Infinity;
        hits.forEach((b, j) => {
          if (i === j) return;
          const dx = Math.max(0, a.x - (b.x + b.w), b.x - (a.x + a.w));
          const dy = Math.max(0, a.y - (b.y + b.h), b.y - (a.y + a.h));
          g = Math.min(g, Math.hypot(dx, dy));
        });
        a.gap = Math.round(g);
      });
      out.tapTargets = hits
        .filter(a => (a.w < 44 || a.h < 44) && !(a.w <= 1 && a.h <= 1))
        .map(a => ({ label: a.label, size: `${a.w}x${a.h}`, y: a.y, gapToNeighbour: a.gap }));

      out.headings = [...d.querySelectorAll('h1,h2,h3,h4')].map(el => {
        const c = cs(el);
        const hidden = /visually-hidden|sr-only/.test(
          String(el.className) + String(el.parentElement && el.parentElement.className));
        return {
          tag: el.tagName.toLowerCase(), size: c.fontSize, lineHeight: c.lineHeight,
          font: c.fontFamily.split(',')[0].replace(/"/g, ''),
          text: txt(el).slice(0, 34), hiddenFromSighted: hidden || undefined,
        };
      });

      out.measure = [...d.querySelectorAll('p,li')].map(el => {
        const t = txt(el), b = el.getBoundingClientRect(), c = cs(el);
        if (!t || b.width < 2) return null;
        const lines = Math.max(1, Math.round(b.height / (parseFloat(c.lineHeight) || 24)));
        return {
          size: c.fontSize, colWidth: Math.round(b.width),
          charsPerLine: Math.round(t.length / lines), text: t.slice(0, 26),
        };
      }).filter(Boolean).filter(r => r.charsPerLine < 45 || r.charsPerLine > 75);

      out.sections = [...d.querySelectorAll('main>*,body>header,body>footer,body>section')]
        .map(el => {
          const b = el.getBoundingClientRect();
          if (b.height < 4) return null;
          const h = el.querySelector('h1,h2,h3');
          return {
            id: el.id || String(el.className).split(' ')[0],
            y: Math.round(b.y + w.scrollY), height: Math.round(b.height),
            heading: h ? txt(h).slice(0, 28) : '',
          };
        }).filter(Boolean);

      out.aboveFold = [...d.querySelectorAll('body *')].filter(el => {
        const b = el.getBoundingClientRect();
        if (b.top >= vh || b.bottom <= 0 || b.width < 2) return false;
        const own = [...el.childNodes].filter(n => n.nodeType === 3)
          .map(n => n.textContent.trim()).join('').trim();
        return own.length > 0 || ['IMG', 'BUTTON'].includes(el.tagName);
      }).map(el => {
        const b = el.getBoundingClientRect();
        return `${el.tagName.toLowerCase()} @${Math.round(b.top)}-${Math.round(b.bottom)}`
          + ` "${(txt(el) || el.alt || '').slice(0, 34)}"`;
      });

      console.log('%c- horizontal overflow -', 'font-weight:bold');
      console.log(out.overflowX);
      console.log('%c- tap targets under 44px -', 'font-weight:bold');
      console.table(out.tapTargets);
      console.log('%c- heading scale -', 'font-weight:bold');
      console.table(out.headings);
      console.log('%c- line length outside 45-75 chars -', 'font-weight:bold');
      console.table(out.measure);
      console.log('%c- section heights -', 'font-weight:bold');
      console.table(out.sections);
      console.log('%c- above the fold -', 'font-weight:bold');
      console.log(out.aboveFold);
      return out;
    },

    off() {
      D.querySelectorAll('#' + ID).forEach(el => el.remove());
      if (S.hidden) S.hidden.forEach(el => { el.style.display = ''; });
      D.body.setAttribute('style', S.bodyStyle || '');
      D.documentElement.style.background = '';
      S.frame = null;
      console.log('[cclb] harness removed');
    },
  };

  W.CCLB = CCLB;
  console.log('[cclb] ready - await CCLB.view(375) then CCLB.audit()');
})();
